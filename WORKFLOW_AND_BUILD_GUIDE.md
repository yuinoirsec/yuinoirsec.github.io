# Next.js Architecture, Build Lifecycle & Workflow Guide

This document clarifies how the portfolio's build system works, explains why changes made to certain files get overwritten on rebuild, and provides a clear map of what to edit and the recommended workflow.

---

## 1. Why Were Your Changes Being Overwritten?

If you were editing files inside the **`out/`** directory (such as `out/index.html` or `out/projects.html`), or if you were expecting edits made to build artifacts to persist, **Next.js will automatically erase and rewrite them every time you run `npm run build`**.

```
                         ┌────────────────────────────────────────┐
                         │   SOURCE FILES (Your Real Code)        │
                         │   • src/app/page.tsx                   │
                         │   • src/app/projects/page.tsx          │
                         │   • src/data/projects.json             │
                         │   • public/images/ & public/videos/    │
                         └──────────────────┬─────────────────────┘
                                            │
                                            │  npm run build (next build)
                                            ▼
                         ┌────────────────────────────────────────┐
                         │   BUILD ARTIFACTS (Auto-Generated)     │
                         │   • out/index.html                     │  <-- Wiped & regenerated
                         │   • out/projects.html                  │  <-- on EVERY build!
                         │   • out/_next/static/chunks/           │
                         │   • .next/                             │
                         └────────────────────────────────────────┘
```

### The Key Rule:
> **The AI assistant never edits the build output (`out/` or `.next/`).**
> All changes are made strictly to the source files in `src/` and `public/`. Running `npm run build` simply compiles the source files into fresh static HTML/CSS/JS inside `out/`.
> 
> If you make edits directly inside `out/`, Next.js considers `out/` disposable and completely replaces it on the next build.

## 2. Directory Map: What to Edit vs. What NEVER to Edit

### ✅ EDIT THESE (Single Source of Truth)

| File / Folder | Purpose | How to Edit |
| :--- | :--- | :--- |
| `src/app/page.tsx` | **Homepage content & components**: Hero, About Me, Skills, Experience, Education, Contact. | Edit directly in React/JSX. |
| `src/app/projects/page.tsx` | **Projects archive page**: Filter tabs, project cards, and expandable sections (Lumina Codex, Manuscript, Hizz Gallery). | Edit directly in React/JSX. |
| `src/app/layout.tsx` | **Root HTML wrapper**: Page title, SEO meta tags, Google Fonts, global favicon. | Edit metadata object or HTML tags. |
| `src/app/globals.css` | **Global styling & CSS rules**: Font descender fix (`.gradient-text`), animations, base Tailwind layers. | Edit custom CSS rules. |
| `src/data/projects.json` | **Projects database**: All project metadata (titles, descriptions, tags, bullet points, image links, video links). | Edit JSON array entries. |
| `src/data/projects.ts` | **TypeScript interfaces & typed exports**: `ProjectItem` and category types. | Add new type definitions if schema changes. |
| `public/images/` | **Static images**: Backdrops, avatars, cover stills, flavor variants. | Add/replace image files (`.png`, `.jpg`, `.webp`). Referenced as `/images/filename.jpg`. |
| `public/videos/` | **Static video clips**: Optimized MP4 videos for media campaigns. | Add `.mp4` video files. Referenced as `/videos/filename.mp4`. |
| `tailwind.config.ts` | **Tailwind styling tokens**: Custom colors (`obsidian`, `rose`, `ivory`), font families, keyframe animations. | Add or adjust design tokens. |
| `next.config.mjs` | **Next.js configuration**: Static export configuration (`output: 'export'`), unoptimized image settings. | Rarely needed unless altering deployment flags. |

---

### ❌ NEVER EDIT THESE (Disposable Generated Files)

| File / Folder | Why You Should NEVER Edit It |
| :--- | :--- |
| **`out/`** | **This is the compiled static HTML/CSS/JS output.** Any edits made here will be completely erased the moment `npm run build` is run. |
| **`.next/`** | Next.js internal compilation and build cache directory. Overwritten automatically. |
| **`node_modules/`** | Third-party dependencies installed via npm. Managed exclusively by `npm install`. |
| **`package-lock.json`** | Exact dependency tree lockfile. Auto-generated by npm. |

## 3. Recommended Workflow

### Workflow A: Making Changes with Live Preview (Best & Fastest)

Instead of rebuilding after every small edit, use Next.js's built-in **development server** with Fast Refresh:

1. In your terminal, run:
   ```bash
   cd /home/yui/work/portfolio
   npm run dev
   ```
2. Open your browser to **`http://localhost:3000`**.
3. Edit any file in `src/app/` or `src/data/projects.json` and save it.
4. **The browser updates instantly** without reloading and without losing your place.
5. Your source files are updated safely, and you don't have to wait for `npm run build`.

---

### Workflow B: Testing the Production Static Export

When you are ready to test the final static build that gets deployed to GitHub Pages:

1. Stop the dev server (`Ctrl + C`).
2. Run the production build:
   ```bash
   npm run build
   ```
   Next.js compiles your `src/` files and generates the clean static site in `./out`.
3. Preview the static export locally:
   ```bash
   npm run start
   ```
   This runs `serve out -p 3000`. Open `http://localhost:3000` to inspect the exact static bundle.

---

### Workflow C: Adding a New Project to the Portfolio

You have two easy ways to add projects:

1. **Directly in `src/data/projects.json`**:
   - Place your image in `public/images/your-project.jpg`.
   - Open `src/data/projects.json` and add an object to `creativeProjects` or `technicalProjects`.
2. **Using the helper script**:
   ```bash
   node scripts/add-project.js --title "My Project" --category media --image "/path/to/image.jpg"
   ```
   The script updates `src/data/projects.json` and copies the image to `public/images/`.

## 4. Summary Checklist When Something Seems Missing

- **Did you edit a file in `out/` instead of `src/`?**
  Always edit `src/app/page.tsx`, `src/app/projects/page.tsx`, or `src/data/projects.json`.
- **Did you run `npm run build` after editing `src/` if viewing via `npm run start`?**
  `npm run start` serves the static `out/` folder. It will not reflect new changes in `src/` until you run `npm run build`. (Alternatively, use `npm run dev` to see changes live without rebuilding).
- **Is the browser caching an old asset?**
  Hard-refresh with `Ctrl + Shift + R` (or `Cmd + Shift + R`).
